# PeerProof 최신 공시 재무 추출기 — LTM 제외 버전 (v3 검토 확정본)

## v3 검토 결과

v2의 기존 24개 테스트와 APR 실데이터 검증은 그대로 통과했다.
추가로 재현한 다음 문제를 수정했으며, 총 31개 테스트(APR 포함)를 통과했다.

| 문제 | 수정 |
|---|---|
| 동일 숫자·다른 통화 보고서가 같은 것으로 처리됨 | 중복 판정에 통화·단위 포함 |
| 종료일·숫자가 같으면 시작일이 달라도 같은 것으로 처리됨 | 시작일·종료일·기간 유형 포함 |
| Q1 누적 값 `bad` 같은 형식 오류가 3개월 값으로 대체됨 | 누락일 때만 대체. 형식 오류는 invalid 유지 |
| 결산월 문자열 `"12"`가 12월 외 기업으로 거부됨 | 문자열·정수 결산월 모두 처리 |
| 접수일 메타데이터가 잘못되면 기준일 뒤 접수번호도 통과함 | 실제 접수번호 날짜와 메타데이터 접수일 대조 |

금액·기간이 같은 중복은 안정적으로 대표본을 선택하고 모든 후보 출처를
`compatible_duplicate_sources`에 기록한다. 접수번호 정렬은 숫자·기간·통화가 동일할 때만 사용한다.
기준일은 프로젝트 분석 시점의 정책이며 최초 신고 전날로 일괄 강제하는 회계 규칙이 아니다.

## v2 변경점 (v1 대비)

| # | 변경 | 이유 |
|---|---|---|
| 1 | `--as-of` **필수** | 기준일 없이 실행하면 상장 후 보고서가 최신으로 선택됨 (실증 확인) |
| 2 | `equity_parent_begin`, `total_equity_begin` 추가 | ROE(11번) 평균자본의 시작값. 같은 보고서 BS의 `frmtrm_amount`(전기말) |
| 3 | 1분기(Q1)만 누적 필드가 비면 3개월 값 사용 | Q1은 3개월=누적. 반기·3분기는 기존대로 대체 금지 |
| 4 | 같은 날 같은 기간 보고서 2건의 **숫자가 같으면** 충돌로 보지 않음 | v1은 접수번호가 달라 항상 오류 |

| 6 | 테스트 15 → 24개, APR 실데이터 정답 테스트 추가 | `PEERPROOF_DATA` 지정 시 실행 |

## 이번 버전에서 확정한 범위

- 기업마다 **수집된 재무 API 원본 중 재무기간 종료일이 가장 최근인 보고서**를 선택한다.
- 그 종료일에 연결(CFS)과 별도(OFS)가 모두 있으면 연결을 우선한다.
- 같은 종료일·같은 재무 범위에서는 최근 접수일의 공시를 선택한다.
- 같은 날짜의 서로 다른 접수번호 결과가 충돌하면 자동 확정하지 않는다.
- 선택한 보고서 안에서 1~8번과 전체 순이익을 추출한다. 보고서 사이 숫자를 합치지 않는다.
- 연간은 FY, 반기·분기는 연초부터 해당 기말까지 YTD 값을 사용한다.
- LTM, 단순 연환산, 9~16번 비율·차액, PER 계산은 하지 않는다.

정정 공시의 접수일이 최신이라고 해서 오래된 재무기간이 최신 실적으로 바뀌지는 않는다.
본 코드는 인터넷에서 신규 공시를 수집하는 도구가 아니다. 기존 개발자의 다운로드 단계가 원본을 제공한다.

## 파일 구성

1. `finance_latest.py`: 독립 실행·함수 호출 모두 가능한 추출 모듈
2. `test_finance_latest.py`: 예외·기간·계정 구분 + APR 실데이터 정답을 확인하는 31개 테스트
3. `APR_latest_report_example.json`: 제공된 data.zip을 실행한 APR 결과
4. `README_KO.md`: 이 안내

Python 3.10 이상, 추가 패키지·유료 API·새 인증키 없이 실행 가능하다.

## 실행

네 파일을 한 폴더에 풀고, 그 폴더에서 실행한다.

```bash
python finance_latest.py data.zip --output finance_latest_output.json --as-of 2023-12-21
```

개발자가 기존 재무 원본 폴더를 사용하면 다음과 같다.

```bash
python finance_latest.py "data/processed/에이피알/finance/raw" --output finance_latest_output.json --as-of 2023-12-21
```

CLI의 `--as-of`는 **필수**이며 해당 날짜를 포함한다. LTM 기능이 아니다.
- 최초 신고 이전의 후보 선정을 재현하면 최초 신고 접수일 전날을 사용한다. APR 예시는 `2023-12-21`이다.
- 기존 APR 파일럿처럼 이후 특정 시점까지 공개된 자료를 분석하면 그 시점(예: `2024-02-13`)을 사용할 수 있다.
- 위 두 날짜는 분석 질문이 다르다. 2024-02-13이 그 자체로 미래정보 오류라는 뜻은 아니다.
- 대상기업·비교기업에는 같은 정보 기준일을 적용하고, 사업 프로필·뉴스·가격 단계의 정책도 일치시킨다.
- 제공된 APR 재무 원본에서는 두 날짜의 선택 결과와 13개 값이 동일함을 확인했다. 다른 기업까지 같다고 보장하지 않는다.
- Python 함수 `extract_report`를 직접 호출하는 개발자는 공통 `as_of` 인자를 반드시 전달한다. 함수의 기본 None은 기존 단위 테스트·단일 원본 점검용이며 운영 파이프라인에서 사용하지 않는다.

테스트:

```bash
python -m unittest -v test_finance_latest.py
# APR 실데이터 정답 테스트까지 실행
PEERPROOF_DATA=data.zip python -m unittest -v test_finance_latest.py
```

## 원본 입력 형식

현재 `data.zip`의 `finance/raw/*.json`을 그대로 지원한다.
wrapper에는 `fs_div`와 `statements`가 있으며 각 행에는 회사번호·보고서 코드·접수번호 등이 있다.
공식 API 응답의 `list` 형식도 지원하지만, API 요청 당시의 `fs_div`를 wrapper에 함께 저장해야 한다.
PDF·HTML·공시 문장·기존 finance_profile.json을 이 모듈의 숫자 원본으로 넣지 않는다.
정기 재무 API가 없는 기업은 별도 원문 표 추출기가 필요하며 이번 코드에 포함하지 않는다.

기본 날짜는 12월 결산·정상 12개월 회계연도를 가정하고 `period_date_basis`에 기록한다.
12월 외 결산기업 또는 짧은 회계연도는 원본 wrapper에 검증된 `period_start`, `period_end`를 추가한다.
두 날짜는 FY/YTD 누적기간이어야 한다. 3분기 단독 3개월 기간을 입력하면 안 된다.
`fiscal_year_end_month`를 12 외 값으로 지정하고 실제 날짜를 누락하면 추출이 거부된다.

## 출력과 UI 연결

```python
result["companies"][corp_code]["context"]
result["companies"][corp_code]["accounts"]["revenue"]["value"]
result["companies"][corp_code]["accounts"]["revenue"]["status"]
```

UI의 주요 16개 행은 유지한다. 내부 원천 입력은 더 많다.

| UI | 표준 입력 |
|---|---|
| 1 매출액 | revenue |
| 2 영업이익 | operating_income |
| 3 지배주주 순이익 | net_income_parent |
| 4 자산총계 | total_assets |
| 5 부채총계 | total_liabilities |
| 6 자본총계 | total_equity |
| 7 지배주주 자본 | equity_parent |
| 8 영업현금흐름 | operating_cash_flow |
| 숨김 입력: 전체 순이익 | net_income_total |
| 다음 단계용 원천 입력 | ppe_purchase_cash, intangible_purchase_cash |
| 다음 단계용 원천 입력 (ROE 시작값) | equity_parent_begin, total_equity_begin |

CAPEX 구성값은 원문 부호 그대로 보관한다. 양의 지출 표준화와 합산은 다음 계산 단계에서 한다.
ROE 시작 자본은 같은 보고서 BS의 `frmtrm_amount`(전기말)에서 추출한다.
정상 회계연도의 FY/YTD에서는 통상 기간 시작 직전 잔액이다. `period_end`는 기간 시작일 전날로 기록한다.
짧은 회계연도·결산기 변경·사용자 지정 기간은 BS 비교 열 날짜가 이 날짜와 일치하는지 원문에서 확인해야 한다.
API의 실제 날짜가 제공되지 않는 기본 케이스는 `context.period_date_basis`의 12월 결산 가정을 따른다.
같은 보고서의 비교 열을 쓰는 것은 재작성 일관성에 유리하지만 모든 회계 비교 가능성을 자동 보증하지 않는다.
전체 순이익은 숨김 입력으로 저장해도 되지만 근거 보기에는 공개한다.

상태:
- `found`: 계정과 필요한 기간 금액을 추출함. 감사·재작성·경제적 비교 가능성을 모두 검증했다는 뜻은 아니다.
- `missing`: 계정 또는 필요한 금액이 없음. 0으로 바꾸지 않는다.
- `ambiguous`: 같은 우선순위의 계정 값이 충돌함.
- `invalid`: 금액의 형식이 잘못됨.

부호는 유지한다. 적자·음수 CFO·음수 자본도 추출할 수 있다.
API 원문 숫자는 기본 단위 1로 저장한다. KRW면 원 단위이다. 화면의 억원 변환은 표시 단계에서 한다.
통화를 임의로 KRW로 변환하지 않는다. 통화가 다른 기업 간 금액 비교에는 별도 변환이 필요하다.

## 계정·기간 선택 원칙

- 재무제표 구분(BS/IS/CIS/CF)을 먼저 제한한다.
- 표준 계정 ID를 우선한다. 없으면 제한된 계정명의 **완전 일치**를 사용한다.
- 매출을 찾기 위해 모든 '수익' 계정을 부분 검색하지 않는다.
- 전체 NI와 parent NI를 각각 추출한다. CFS에서 parent가 없다고 total을 복사하지 않는다.
- OFS의 NI/자본은 parent 대응 입력에 매핑할 수 있으며 그 근거를 `standalone_mapping`으로 기록한다.
- 분기·반기 IS/CIS는 `thstrm_add_amount`를 쓴다. 반기·3분기는 없으면 3개월 값으로 대체하지 않는다(missing). 1분기만 3개월=누적이므로 `thstrm_amount`로 대체한다.
- BS는 `thstrm_amount` 기말 잔액을 쓴다.
- CF는 제공된 OpenDART 원본 방식에 따라 `thstrm_amount` 누적 값을 쓴다. 손익계산서의 3개월 필드 규칙을 CF까지 적용하지 않는다.
- 일반적인 API 재무표 구조를 지원한다. 사용자 정의 계정·특수 양식이 매핑되지 않으면 missing/ambiguous를 반환한다. 모든 기업의 숫자를 강제로 채우는 코드는 아니다.

참고 공식 명세: https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020

## 개발자에게 전달할 변경점

1. 기존 다운로드 단계는 유지하고 wrapper를 본 모듈에 전달한다.
2. 기존 extractor 결과와 본 모듈 결과를 동시에 계산 원천으로 쓰지 말고 하나로 연결한다.
3. 기존 `net_income`은 total 의미를 유지한다. 호환이 필요하면 검증된 `net_income_total` 결과에만 연결한다.
4. 회사 프로필의 Finance 영역에 `companies[corp_code]`를 연결한다. 기존 JSON 구조를 자동 덮어쓰지 않는다.
5. 화면에 FY/반기 누적/9개월 누적·종료일·연결/별도를 표시한다.
6. 이번 버전은 기업별 최신 공시를 허용한다. 서로 다른 기간의 순이익을 넣은 PER 평균은 별도 정책을 정하는 다음 단계 과제로 남긴다.
7. **비교기업 추출에도 대상기업과 같은 `--as-of`를 전달한다.** 프로젝트 분석 설정에서 공통 날짜를 가져오고, 최초 신고 이전 분석이면 최초 접수일 전날로 설정한다.
8. 기존 다운로더는 최상위 날짜를 읽지만 수집 메타데이터는 `collection_rule` 안에 날짜를 둔다. 경로를 맞춰야 한다. `ipo_date`라는 이름과 실제 신고서 접수일을 혼동하지 말고 정보 기준일은 별도 `analysis_as_of`로 관리한다.
9. 12월 외 결산기업 대비: 다운로더가 DART `company.json`의 `acc_mt`(결산월)를 wrapper의 `fiscal_year_end_month`로 저장하면, 본 모듈이 12월 외 결산기업을 조용히 잘못 처리하지 않고 거부한다.
10. 기존 `finance/matcher.py`는 이 모듈과 함께 쓰지 않는다. 계속 쓴다면 `PERIOD_PRIORITY`에서 FY가 Q3보다 낮게 정렬되는 버그를 먼저 고친다.

본 패키지는 기존 저장소를 변경한 패치가 아니라 독립 모듈이다. 가져와 연결하는 단계가 필요하다.
